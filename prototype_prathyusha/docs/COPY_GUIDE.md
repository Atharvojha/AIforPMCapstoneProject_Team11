# COPY_GUIDE — one plain vocabulary for the whole product

Written after user feedback (2026-11-10): the first UI used internal jargon ("requirement gate", "spec mismatch", "provisional", "coverage", "sibling variant") that students did not understand. Rule: **if a word needs explaining, replace it; if it can't be replaced, explain it where it appears and in How it works.**

| Internal idea | What the student sees | Explained where |
|---|---|---|
| Requirement gate | **Your must-haves** — "Does it meet your must-haves?" | report §1 |
| Met / Not met | ✓ Yes / ✕ No | legend box |
| Spec mismatch | ✕ **Below what you asked** (the listing itself falls short) | legend, How it works |
| Unknown | ? **Can't tell yet** ("never means yes") | legend |
| Dealbreaker (≥2 owners, priority) | ! **Serious problem** | legend |
| Watch-out | ◐ **Worth checking** | legend |
| Strong / OK / Weak | ✓ **Good** / ◐ **OK, with trade-offs** / ✕ **Poor** | How it works |
| Not enough evidence | ? **Not enough information** | |
| Coverage | **How much we know** | report §3–4 |
| Provisional | **Early result** (we are still reading reviews) | banner + tag |
| Sibling variant | **Similar model** (e.g. different processor), never counted as this laptop | report §6 |
| Manufacturer claim | **Maker's claim** (not independent proof) | |
| Spec / Lab / Owner (■◆●) | **Listing details / Lab test / Owner reviews** | "Based on" column |
| validation unconfirmed | **Not double-checked yet** | |
| Set aside / excluded | **Not counted** (copies, too short, owner changed hardware) | report §5 |
| Evidence drawer | **Read the full review** | |
| Claim verdicts | ✓ The evidence supports this · ✕ The evidence says otherwise · ◐ Depends on the situation · ? Not enough evidence | claim page |
| Claim lanes | **Supports it / Goes against it / Doesn't count here** | claim page |

Voice: plain, short, second person; say what we found and what it means for the student; never "AI says"; errors say what happened and what to do; never imply a missing finding means safety.

## Added 2026-11-11
Happy % = of owners who wrote about a topic, the share who were positive (mixed counts half) · "Not enough reviews" = fewer than 3 owners · "Our suggestion" = rule of thumb, not a measurement · "Misses a need" = below a number the user gave · "Below our suggestion" = below a number we suggested · "What we understood" = the parsed needs, always editable by changing the text.


## Final state vocabulary (2026-11-11)
| Internal idea | What the student sees |
|---|---|
| verdict supported / contradicted / mixed / insufficient (Lie Detector) | ✓ Checks out / ✕ Doesn't add up / ◐ Partly, or it depends / ? Only the seller's word |
| claim checker verdicts | ✓ The evidence supports this / ✕ The evidence says otherwise / ◐ Mixed: no clear answer / ? Not enough evidence |
| importance 0 to 3 | Don't care / Nice to have / Important / Must have |
| unsourced suggestion | "Rule of thumb, no source" (vendor-sourced: the link text, e.g. "Docker Desktop on Windows: 8 GB RAM") |
| brand-level owner evidence | "owners of ASUS laptops in general, NOT this model" |
| seller questions | "Ask the seller", "Ask:" |
| no owner data for a model | "We have no owner reviews of this exact model" + "Look it up online" |
| model or rules splitter | "How this was done" card |
| ignored instruction lines | "Some lines looked like instructions to the software, so we ignored them." |
Rules kept: never "AI says"; never "buy this"; unknown is said as unknown; seller numbers are "the seller's number" until shown.
