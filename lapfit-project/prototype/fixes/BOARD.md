### FE-D · 14 Nov, owner feedback round (tsc clean, vitest 290 green)
Causes found:
- (a) Explore showed "0 of 14" for Apple + under 1.5 kg because the catalog list was cached in sessionStorage under `lapfit.catalog` from before weight/screen/market/image existed, so every row had no weight. Fix: key is now `lapfit.catalog.v2` (old key deleted on load) and a saved list is only trusted when every row has `weight_kg` and `display_size` keys; otherwise it is fetched again. A laptop with an unknown value is never dropped silently: Explore says "N laptops have no recorded weight, so they are left out" with an "Include them" button; cards say "weight not recorded".
- (d) The sort chips posted `{sort}` with no `needs` through ctx.action, so the server said "Tell me what you need" and the app added a "Sort by ..." user bubble (a new turn). Fix: `useThread.replaceTurn(turnId, body)` re-requests and REPLACES that turn's reply (no new turn, no user bubble, dimmed "Updating these results…", scroll kept). `ctx.resort(body)` is set per turn by ThreadView. Sort chips send `{needs: block.needs ?? saved needs, sort}`; Understood "Update results" and budget edits send `{needs}` the same way. The old `{sort}`-alone fallback is gone. If the server errors or answers with the "Tell me what you need" choices (no cards), the old reply stays and a calm inline note says so. Follow-up questions are still new turns.
- (c) Details jump: I found no timer-driven code path that changes the route, and no hash change. Real code causes fixed: (1) BottomSheet's effect depended on `onClose`, so any parent re-render with a new function ran the cleanup, which restores focus to the opener (that scrolls the page back to the card) and then re-focuses the sheet; it now reads onClose from a ref and restores focus only on a real close. (2) ThreadView scrolled to the end of the thread on first paint and on every `busy` flip, which threw a long Explore page to its bottom; it now follows only a NEW turn. (3) The most likely cause of "back to the Ask homepage after a few seconds" is a Vite full reload (we were editing files) wiping React state: the thread, route and open Detail were all in memory. Now the Ask and Explore threads (last 6 finished turns, 300 KB cap), the route (`lapfit.route.v1`, restored when the address has no hash) and the open Detail card (looked up again in the saved replies) are kept in sessionStorage; "Start over" and the new "New search" button in the chat header clear them. Could not reproduce a timer-driven jump in the app itself; if it still happens without a reload, tell me the screen and I will look at the console.
- New: `web_picks` block (components/blocks/WebPicks.tsx, fixture test/fixtures/web_picks.json, gallery `/?mock#/gallery/web_picks`). Search box on Explore with "Search the web too" sends `{action:'web_search_laptops', query}`.
